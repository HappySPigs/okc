# Performance Test Instructions

## Purpose

Watcher 의 성능 특성을 기술한다. **중요**: 이 프로젝트는 결정에 따라 **정량 NFR 게이트를 두지 않는다**
(응답시간/처리량/동시성 수치 목표 없음). 성능은 설계 수준의 **정성 보장**으로 다루며, 부하/처리량 성능
테스트는 **이연** 항목이다.

## Performance Requirements

- **정량 목표 없음(정성만)**: 수치 SLO(응답시간 ms, 초당 처리량, 동시 사용자, 오류율 임계)는 정의하지 않았다.
  Watcher 는 사용자당 로컬 볼트를 한 서버로 단방향 동기화하는 백그라운드 데몬이라, 다중-테넌트 처리량 목표가
  성립하지 않는다.

## 정성 성능 설계 포인트 (코드로 성립, 확인됨)

- **스트리밍 전송 / 전체 파일 메모리 미적재**: 업로드는 blob 을 `Box<dyn Read>` 리더로 열어 청크 경계
  (`chunk_threshold_bytes` / `chunk_size_bytes`, 기본 8 MiB / 1 MiB)로 전송한다. 파일 전체를 메모리에 적재하지
  않으므로 대용량 파일에서도 메모리 사용이 파일 크기에 비례해 증가하지 않는다.
- **경계된 메모리(bounded memory)**: 사이클은 매니페스트(경로+해시+크기 메타) 단위로 작업하고, IPC 프레임은
  고정 상한(`MAX_FRAME_BYTES` 8 MiB)으로 제한되며, 로그는 회전 임계(기본 10 MiB x 보존 3)로 상한을 둔다.
- **단일 직렬 사이클 + drain-to-latest**: 트리거 폭주는 `coalesce_to_latest` 로 최신 하나만 남겨 흡수한다
  (중복 사이클 억제, PROP-U8-05). 파일 변경 버스트가 몰려도 사이클은 중첩 없이 직렬 실행된다.
- **디바운스 + 주기 재조정 백스톱**: U2 디바운스(기본 2s)로 저장 폭주를 합치고, 주기 재조정(기본 900s)은 busy
  신호를 관측해 진행 중 사이클과 중복을 억제한다.
- **재개 오프셋 + 백오프**: 실패 전송은 재개 오프셋을 지속하고, `Transport` 실패만 지수 백오프(full jitter,
  cap 300s 기본)로 재예약한다 — 실패 시 서버·네트워크에 과부하를 주지 않는다.

## Setup / Run

정량 성능 테스트 하네스(부하 생성기, 벤치 스위트)는 **도입하지 않았다**. 별도 실행 명령이 없다.

- **부하 테스트(load test)**: 이연.
- **처리량/스트레스 테스트**: 이연.
- **벤치마크(criterion 등)**: 미도입.

## Analyze Performance Results

- **측정 지표/실측값**: 없음(정량 게이트 부재). 위 정성 설계 포인트가 유일한 성능 보장이다.
- **Results Location**: 해당 없음.

## 향후(이연) 작업

라이브 okc 서버가 가용해지면 다음을 추가할 수 있다: 대용량 볼트 초기 스캔 소요, 대용량 파일 청크 업로드 처리량,
장시간 구동 메모리 안정성(누수 부재) 프로파일. 현재는 정량 목표·하네스 모두 범위 밖이다.
