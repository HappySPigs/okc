# 페르소나 — okc-hooks "Watcher"

**단계**: INCEPTION → User Stories (Part 2 — 생성)
**작성일**: 2026-09-07
**실행 모델(권위 있는 확정)**: Watcher는 사용자 **본인의 개인 데스크톱**(macOS / Windows / Linux)에 설치되어 **GUI 없이 백그라운드 데몬/서비스로** 상주합니다(nginx 방식). 전용 GUI 창은 없으며, 원격 서버도 아닙니다. 모든 상호작용은 **편집 가능한 config 파일 + 동반 CLI(start / stop / status / "sync now" / view-history) + 구조화 로그 + 헬스 체크**를 통해 이루어집니다. 시스템 트레이/메뉴바 상태 아이콘(FR-18)은 **데스크톱 세션이 있을 때만 쓰는 선택적 편의 기능**이며, 어떤 스토리도 트레이 존재에 의존하지 않습니다.

**페르소나 집합(Q4=B + 데몬 명확화 확정)**: 정확히 **2개**. 별도의 "Headless Operator"나 "서버 관리자" 페르소나는 두지 않습니다 — 데몬 운영은 P1의 **정상(normal) 모드**이기 때문입니다. 미래 웹 서비스는 페르소나가 아니라 DEP-01..07 외부 계약으로 표현합니다.

## P1 — Vault Owner (주 사용자 / 데몬 운영자)

**원형(archetype)**
Obsidian 볼트를 자기 개인 데스크톱에서 관리하며, Watcher를 OS 서비스로 **한 번 설치·설정한 뒤 잊고 지내려는** 실용주의 1인 운영자. 온보더(설치·토큰·볼트 지정), 설정 후 방치형 운영자(set-and-forget), 문제 해결자(장애 조치), 오프라인 사용자 등의 서로 다른 여정을 **한 사람이 모두 흡수**합니다. GUI 앱 사용자가 아니라, 백그라운드 서비스를 config와 CLI로 다루는 데 익숙한 사람입니다.

**목표(goals)**
- 볼트 변경이 사람 개입 없이(FR-01/FR-06) **손실 없이(FR-03, NFR-03)** 서버로 자동 동기화되게 한다.
- 대용량/초기 볼트도 재개 가능(FR-08)하고 효율적(FR-07 have/want)으로 올린다.
- 설치 후 방치해도 크래시/재시작(FR-23), 오프라인(FR-11/FR-12), 이벤트 손실(FR-04)에도 스스로 회복한다.
- 데몬을 CLI로 확실히 제어한다 — 시작/중지, `status`, "sync now", 일시정지/재개(FR-21, Q11=D).
- 상태와 문제를 **로그 + `status` + 헬스 체크**로 즉시 파악한다(NFR-15). 중대 오류는 능동적으로 통지받는다(FR-19).
- OS 서비스로 자동 시작(FR-21)하고, 자동 업데이트가 실패하면 자동 롤백(FR-20)되어 손이 덜 가게 한다.

**불만/pain points**
- 볼트 폴더가 언마운트/이동/삭제됐을 때 "전부 삭제"로 오판해 **파괴적인 빈 커밋**이 서버로 나가는 상황(FR-09 위험) — 안전 가드(US-E1-06)가 필요.
- 조용히 죽거나 이벤트를 놓쳐 **모르는 사이에 동기화가 멈추는** 것. 로그를 열어보기 전엔 눈치채기 어려움(FR-04 백스톱, FR-19 능동 통지로 완화).
- 서버가 아직 없어(DEP-01..07) 어디까지가 "지금 되는 것"이고 어디부터가 "서버 대기"인지 헷갈림.
- 대용량 초기 업로드가 도중에 끊기면 처음부터 다시 올려야 할까 봐 불안(FR-08 재개로 완화).
- 자동 업데이트가 데몬을 망가뜨릴까 봐 걱정(FR-20 헬스 체크 + 자동 롤백으로 완화).
- GUI가 없으니 상태 확인이 불편할까 봐 걱정 — `status`/헬스 체크/로그가 그 역할을 확실히 대신해야 함.

**기술 수준(technical level)**
중급~고급. 터미널/CLI, 텍스트 config 파일 편집, 로그 tail, OS 서비스 관리자(launchd / systemd / Windows Service)에 익숙. 개발자·파워유저 성향으로, JSON/TOML/YAML류 config와 종료 코드·헬스 엔드포인트를 자연스럽게 다룸. 다만 서버/분산 시스템 운영자는 아니며, **자기 한 대의 데스크톱**만 운영.

**환경 / 제어 표면(environment & control surface)**
- **PRIMARY**: 편집 가능한 **config 파일**(볼트 경로, T_debounce, T_recon, 임계값 S, 백오프, 토큰 등) + **동반 CLI**(`start` / `stop` / `status` / `sync now` / `view-history` / `pause` / `resume`).
- **PRIMARY 관측 표면**: 구조화 로그(FR-17) + `status` 명령 + 헬스 체크(NFR-15).
- **설치/수명주기**: OS 서비스로 설치·자동시작(launchd / systemd / Windows Service, FR-21).
- **토큰 경로**: config/env(키링 없는 경로)가 기본, OS 보안 저장소는 선택적 강화.
- **OPTIONAL**: 데스크톱 세션이 있을 때만 트레이/메뉴바 상태 아이콘(FR-18) — 없어도 모든 기능이 동작.

## P2 — 프라이버시 민감 Vault Owner (관점 변형)

**원형(archetype)**
P1과 **동일 인물**이되, 프라이버시/노출 관점으로 볼 때의 얼굴. 볼트에 민감 정보(비밀·개인정보)가 있을 수 있음을 인지하고, "원시 볼트가 통째로 서버에 올라간다"는 사실(RISK-01)과 그것이 **연속적·비가역적**이라는 성질을 분명히 이해한 상태에서 동의하고 싶어 함. Security Baseline이 OFF(Q1=B)라는 트레이드오프를 스스로 감수하는 신중한 소유자.

**목표(goals)**
- 첫 실행에서 **RISK-01 공개 고지**를 명시적으로 읽고 확인(informed consent 기록)한 뒤에만 업로드가 시작되게 한다(US-E4-04).
- **상시 동의(standing consent)**의 부여·조회·철회 경로를 config/CLI로 확실히 확보한다(FR-14, US-E4-05/US-E4-06).
- 동의를 철회하면 **로컬에서 즉시 업로드/커밋이 차단**되도록 한다(감시·큐 적재는 유지, Q6=B; DEP-02는 서버 대기).
- 무엇이 언제 어떤 해시로 올라갔는지 **로컬 append-only 히스토리**로 감사(audit)할 수 있게 한다(FR-16, US-E5-03).
- 데몬 제거 시 로컬 평문 산출물(히스토리·매니페스트·큐·로그)과 저장 토큰이 **정리(cleanup)** 되도록 한다(US-E6-04).
- 토큰이 config/로그/평문 산출물에 노출되는 표면을 최소화하고, TLS로 전송이 보호되는지 확인한다(NFR-06).

**불만/pain points**
- 서버가 없어(DEP-02) 철회가 **전진 방향(forward-only)** 일 뿐, 이미 올라간 내용은 회수 불가 — 이 한계가 투명하게 고지되지 않으면 불신(US-E4-04/06가 명시).
- 상시 동의 + 자동 동기화라 나중에 실수로 추가된 비밀도 **자동 업로드**됨(RISK-01) — 어떤 스냅샷이 나갔는지 사후 추적할 감사 수단이 꼭 필요.
- Security OFF라 로그·히스토리·매니페스트·큐가 OS 보안 저장소 밖 **평문**으로 디스크에 남음(RISK-01) — 제거 시 확실히 지워지길 원함.
- 동의 상태·마지막 업로드 내역을 GUI 없이 어떻게 확인·철회하는지 명확한 CLI/config 경로가 없으면 불안.

**기술 수준(technical level)**
P1과 동일한 중급~고급 데몬 운영자. 추가로 데이터 노출/보안 트레이드오프에 대한 이해가 높아, "무엇이 어디에 평문으로 남는가", "TLS/토큰이 실제로 무엇을 보호하는가"를 따져 물음. 규정·비밀 데이터가 관련되면 재검토를 요구할 판단력이 있음.

**환경 / 제어 표면(environment & control surface)**
- P1과 동일한 표면(config 파일 + CLI + 로그 + 헬스 체크; 트레이는 선택적)을 공유하되, 다음에 집중:
  - 최초 실행 공개 고지 확인 및 동의 부여/조회/철회를 **config 설정 + CLI 명령**으로 수행(US-E4-04/05/06).
  - `view-history` CLI로 로컬 감사 로그 조회(US-E5-03).
  - 제거/폐기 CLI 경로로 평문 산출물 + 토큰 정리(US-E6-04).
- 미래 서버 강제 항목(DEP-02 동의 강제 등)은 **blocked-on-server**, 클라이언트 관측 동작은 **assumption-based (mock contract)** 로 검증.
