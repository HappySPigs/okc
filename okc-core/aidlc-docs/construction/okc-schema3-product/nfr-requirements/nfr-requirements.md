# NFR Requirements — okc-schema3-product

## Scope and interpretation

These requirements restate current normative constraints and measured status.
Safety ceilings are not performance promises. Local results are not remote or
cross-platform release qualification.

## Performance requirement caveat

The current ingestion-only probe processed 10 Vaults/100,000 notes/25.6 MB in
174.569 seconds with 5,360,336,896 bytes maximum RSS and zero provider calls.
It does not exercise the 20 GB workload or semantic candidate path and must
report `qg_006_pass: false`. No current numerical time/RSS budget or reference
machine is accepted; this document does not reuse the historical V1 target.

## Availability and recovery

OKC is a local tool/library, so service uptime and multi-zone availability are
not applicable. Reliability is expressed as deterministic resume, explicit
failure state, single-writer consistency, safe cleanup, no-clobber publication,
and artifact verification. Automated power-loss recovery and complete orphan
management are not implemented.

## Security requirements

- Treat all external content and paths as data, never executable authority.
- Reject lossy decoding, duplicate JSON/YAML ambiguity, path aliases, unsafe
  links, unplanned artifact content, and credential-bearing options.
- Keep source/output/project/workspace roots separate.
- Use platform certificate verification, no redirects, bounded transport, and
  sanitized errors for remote profiles.
- Keep verification integrity distinct from publisher authenticity.

## Usability requirements

- CLI help and parse behavior form a stable current-only contract.
- Non-interactive ambiguity fails rather than selecting a project silently.
- SDK operations return bounded jobs and structured errors without stdout/stderr side effects.
- TUI must restore terminal state and render hostile controls safely.
- Product limitations must remain visible in user documentation.

## Release acceptance

Stable 0.3.0 requires every QG-001 through QG-008 result on its declared matrix,
including semantic scale, native package parity, reproducibility, checksums,
SBOMs, attestations, and required Apple/Windows signatures. Current status is
not ready for release.
