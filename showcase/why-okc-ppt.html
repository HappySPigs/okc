OKC,
왜 필요한가요?

여러 사람이 각자 쌓은 지식을, 누가 무엇을 근거로 승인했는지 되물을 수 있는 하나의 검증 가능한 지식 베이스로 만들어 주는 도구입니다.
Have you ever…

🙋혹시, 이런 적 없으셨나요?

  • Obsidian으로 작업하다 어떤 문제를 멋지게 해결한 세션이 있었는데, 몇 주 뒤 똑같은 상황에서 “그때 어떻게 했더라…” 하며 처음부터 다시 헤맨 적
  • 분명 정리는 해뒀는데, 정작 필요할 때 그 노트를 못 찾은 적
  • 옆 팀·동료가 이미 풀어 둔 세션을, 그런 게 있는 줄 몰라서 똑같이 다시 푼 적
  • 남이 정리해 준 지식을 보며 “그럴듯한데… 이거 진짜 근거가 맞나?” 싶어 못 믿은 적
하나라도 뜨끔했다면, OKC는 바로 그 순간들을 위해 만들었습니다. 잘 풀린 세션은 다시 꺼내 쓰고, 남들이 남긴 세션도 믿고 가져다 쓰게 하는 것 — 그게 출발점이었습니다.
What is it

Q🧩OKC가 뭔가요?

흩어진 Obsidian 노트 모음(Vault)을 하나의 신뢰할 수 있는 지식 베이스로 “컴파일”하는 시스템입니다. 소스 코드를 빌드하듯이 —
여러 팀의 노트를 모아 → AI가 정리안을 제안하고 → 코드가 검증하고 → 사람이 승인해야 → 하나의 결과물이 나옵니다.
The problem

Q❓왜 필요한가요? (핵심)

각자 노트를 아무리 잘 써도, 조직 단위로 합치려는 순간 네 가지 문제가 생깁니다.

출처 소실

합쳐진 문장이 어느 팀 어느 노트에서 왔는지 알 수 없습니다.

모순 은폐

서로 다른 정책·날짜가 매끄러운 한 문장으로 뭉개집니다.

승인 드리프트

승인한 뒤 내용이 바뀌어도 승인 기록은 그대로 남습니다.

버전 혼동

최신 발행본과 낡은 로컬 지식이 조용히 섞입니다.

The core reason

💡“그때 그 세션, 다시 쓰고 싶어요”

  • 내 세션 재사용 — 코딩 중 나온 결정·명령·해결법을 okc-mcp에게 “이번 세션을 관련 노트에 기록해줘” 한마디로 남겨 두면, 다음 작업에서 그대로 다시 꺼내 씁니다.
  • 남의 세션 활용 — 내 것뿐 아니라 동료·다른 팀이 남긴 세션·런북도 부서 공동 아카이브에서 “우리 팀은 전에 이거 어떻게 했지?” 라고 물어 재사용합니다.
  • 믿고 쓰는 재사용 — 가져다 쓰는 지식이 출처가 추적되고 사람이 승인한 검증된 내용이라 다시 의심할 필요가 없습니다.
한 번 잘 해결한 문제를 다음 작업(그리고 다음 사람)의 출발점으로 — 이 지식 순환이 OKC의 심장입니다.
Not just a summary

Q🤖그냥 AI로 요약하면 안 되나요?

AI 요약은 읽기엔 좋지만 믿을 근거가 없습니다. OKC에서 AI는 최종 답이 아니라 제안만 합니다.
누가무엇을
AI분류·합성·비평을 제안 — 소스는 명령이 아니라 검증 대상 근거로 취급
코드근거·해시·누락·비평 심각도를 검증 — Major/Critical 지적이 남으면 컴파일 자체가 막힘
사람명시적으로 승인 — 승인은 대상 해시에 묶여, 내용이 바뀌면 승인도 무효
Why you can trust it

Q그래서 결과를 믿을 수 있나요?

🔁

매번 같은 결과

승인 이후의 compile·verify·explain은 LLM 없이(provider-free) 결정론적으로 동작합니다. 같은 입력이면 byte 단위로 같은 결과가 나오고, 모델·API가 사라져도 내부 정합성을 다시 검증합니다.

📌

버전이 고정됩니다

발행된 지식은 revision pinning으로 고정됩니다. 새 버전이 나와도 예전 버전을 그대로 다시 읽을 수 있고, 파일을 몰래 수정하면 verify가 실패로 잡아냅니다. 히스토리·복원도 지원합니다.

How it flows

Q🛠️실제로 어떻게 돌아가나요? (한 줄)

노트 작성 → okc-hooks 자동 업로드 → okc-web에서 큐레이터 검토·승인
        → okc-core가 결정론적으로 컴파일 → okc-mcp로 사람·AI가 검증된 지식 읽기
Benefits

✅뭐가 좋아지나요?

흩어진 지식이 하나의 검증 가능한 아카이브로 모입니다.

모든 항목의 출처를 되짚고, 모순을 지우지 않고 보존합니다.

결과가 재현 가능하고, 발행본이 조용히 바뀌지 않습니다.

팀원은 워크플로를 안 바꿔도 되고, AI 에이전트는 믿을 수 있는 지식을 그대로 씁니다.

Honest scope

⚠️지금 바로 쓸 수 있나요? (정직하게)

개발 단계 프로젝트입니다. okc-web은 단일 조직·단일 프로세스 해커톤 MVP, okc-mcp은 로컬 알파이며, 현재 산출물은 Markdown 중심입니다. 의미 기반 검색·랭킹, 네이티브 서명, 배포/릴리스 게이트 등은 아직 범위 밖입니다.

이런 경계를 숨기지 않는 이유는 간단합니다 — OKC가 파는 가치 자체가 바로 “검증 가능한 주장”이기 때문입니다.

Take-away

AI 시대의 지식에는 답만큼 “증거”가 필요합니다

OKC는 그럴듯한 요약을 넘어, 누가 무엇을 제안했고 · 어떤 근거가 승인됐으며 · 지금 읽는 내용이 그 승인 결과와 일치하는지 다시 물을 수 있는 조직 지식을 만듭니다.
